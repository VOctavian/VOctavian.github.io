how i build

A request, end to end.

Most backend problems are the same shape: something arrives, something must be decided fast, and something heavy must happen later. Here's the skeleton I keep coming back to.

Thin edgesControllers validate and delegate. Nothing clever at the boundary.
Cache before scaleThe cheapest query is the one you never send.
Push work off the requestIf the user doesn't need to wait, they shouldn't.
Abstract the driverStorage should be swappable, not welded to the domain.

operating manual

What I'm like to work with.

The technical stuff is learnable. This part is what actually decides whether a project lands.

01

Boring in production is the goal

Clever code is a liability at 3am. I optimize for the version a tired teammate can read and change safely six months from now.

02

Measure, then touch

"It feels slow" isn't a diagnosis. Profile, find the actual query, fix that one thing. Most 10x wins are one index and one N+1.

03

Legacy isn't the enemy

It's revenue that already works. I refactor in seams, behind tests, without a rewrite that stops the roadmap for a quarter.

04

Async-first communication

Years of remote work with distributed teams. Written clarity, small PRs, decisions in the open — no one has to be in the same timezone to move.

05

Reviews are teaching, not gatekeeping

Leading a team taught me the review is where standards actually get set. I explain the why, and I'm happy to be the one corrected.

06

AI is a power tool, not a pilot

I use agentic tooling daily to move faster on scaffolding, tests and refactors — and I still read every line before it merges.
